# UNITY-007 follow-up: visual biomes

`LargeIslandTerrain.Build()` reads `WorldSnapshot.Terrain` and generates a heightmap, five colored `TerrainLayer` textures and an ocean plane. Its forest and mountain values currently change height and terrain paint only. No Nature MegaKit prefab, texture or `TerrainData` tree/detail prototype is referenced there. In `IslandView.Rebuild()`, large islands skip `DrawTile()`, which is the only path that creates the starter's primitive trees and rocks. This is why the playable LargeIsland has forest and rock-colored areas without 3D vegetation.

The next terrain pass should create a separate static biome root once from the same snapshot. Use the existing Nature MegaKit models for a small tree, shrub and rock palette, scatter them deterministically within Forest and Mountain cells, and sample the terrain height for each instance. Keep a clear center and valid road/building plots, omit or disable decoration colliders so the Terrain collider remains the click target, and reuse shared materials and meshes. Rebuild or suppress a local decoration group only when its plot becomes occupied. Profile draw calls and memory before increasing density, then consider `TerrainData` tree/detail prototypes or GPU instancing for distant vegetation.

For mountains, vary the height field with several overlapping ridges and add rock clusters on slopes, leaving logical quarry cells usable. For the coastline, smooth the water-to-land height transition at subcell resolution, blend sand into grass by distance from shore and slope, and soften the ocean surface. These visual steps must use the existing `IslandMap` terrain categories and preserve the current placement rules in `WorldGameSession`.
